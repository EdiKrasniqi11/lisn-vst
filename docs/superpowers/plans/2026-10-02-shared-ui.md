# Shared UI: Volume Bars, Speed Strip, Opening Animation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The plugin and the desktop app both show the approved 2C stems screen and the 4A opening animation:
- a volume bar under each stem name;
- a speed strip at the bottom;
- the waves flowing in on the first open.

They also open instantly. In the VST, the Drag mix chip prepares a time-stretched mix in the background.

**Architecture:**
- **New controls:** `VolumeBar` (in `Controls`) and `SpeedStrip` (in `Screens`) are small custom components that never take focus. The editor wires them to `StemPlayer::setVolume` and `setSpeed` (plan 1), and reads them back on every tick.
- **Intro:** `WaveBackground::setIntro (seconds)` offsets the five wave layers and fades the panel. The editor drives it from a `VBlankAttachment`, the first time an editor opens for a processor.
- **Background renders:** a reusable `RenderJob` (a `juce::Thread`) runs `StemPlayer::render` off the message thread. The VST's Preparing chip uses it, and plan 3's Export will too.

**Tech Stack:** JUCE 8.0.15, C++17, CMake + MSVC 2022.

**Spec:** `docs/superpowers/specs/2026-10-01-volume-speed-intro-desktop-look-design.md`, sections "Shared: the UI", "VST only", "Failure cases" and "Testing". The approved boards are in `docs/design/desktop/` (`Stems4.dc.html`, `Stems6.dc.html`, `StemsVst.dc.html`, `Intro.dc.html`) and on the canvas https://claude.ai/artifact/WZAorMYikyGdajfTXVJp2D. **Where this text and a board disagree, the board wins.** The desktop-only parts (title bar, Export, rows without chips, desktop help tips) are plan 3.

## Global Constraints

- **The redesign spec's "Must hold" list:**
  - no ComboBox, TextEditor, PopupMenu or ProgressBar;
  - nothing takes keyboard focus except the editor itself;
  - paint guards path work with `g.clipRegionIntersects`;
  - a stopped player's `processBlock` does no work;
  - the motion frame stays at or under 4 ms (Release bench), intro frames included.
- **Engine API from plan 1 (thread rules):**
  - `setVolume`, `getVolume`, `setSpeed` and `getSpeed` are lock-free and safe from any thread;
  - `mixGains()`, `getFiles()`, `getLoop()`, `getLengthSeconds()` and `isLooping()` are message thread only;
  - `StemPlayer::render` is static and safe on a background thread.
  - Snapshot every render input on the message thread and give the thread copies.
  - `setSpeed` rounds to hundredths.
- **Single stems are always the originals; the mix is what you hear.** Row Drag chips are unchanged.
- **Sizes (boards 2C):**
  - **4 stems:** rows 56 px, waveform 36, mute light 38, row gap 8.
  - **6 stems:** rows 36 px, waveform 24, mute light 30, name 13 px, row gap 6.
  - **Volume bar:** 96 x 3 px under the name, 10 px cream thumb, stem-colour fill on `cream@0.16`.
  - **Speed strip:** 30 px tall, under a divider, at the panel bottom.
  - **VST waveform:** stays 376 px wide plus the chip.
- **Intro (board 4A):**
  - 5 layers, each starting a full width off-screen from alternating sides, then easing in over 1.25 s;
  - each layer starts 0.08 s after the one behind it;
  - the panel fades in and rises 18 px over 0.7 s from 1.05 s;
  - the header and screen fade in over 0.6 s from 1.3 s.
  - It plays once per processor instance. A click skips it, and it's skipped when Windows' client-area animations are off.

**Interfaces:**
- **Produces (plan 3's Export reuses it):**
  ```cpp
  // StemPlayer::render on its own thread. Every input is copied at start(); the owner polls the state on the message thread.
  // The destructor cancels and joins.
  class RenderJob : private juce::Thread
  {
  public:
      struct Request { juce::Array<juce::File> stems; std::vector<float> gains; double startSec = 0, endSec = 0, speed = 1.0; juce::File dest; };
      enum class State { idle, running, done, failed };
      RenderJob();
      ~RenderJob() override;                       // cancel()
      void start (Request);                        // cancels any running render first
      void cancel();                               // stops within one chunk, joins; the state goes back to idle
      State getState() const { return state.load(); }
      float getProgress() const { return progress.load(); }   // 0..1
      juce::File getDest() const;                  // the current request's dest (message thread)
  private:
      void run() override;
      Request request;
      std::atomic<State> state { State::idle };
      std::atomic<float> progress { 0.0f };
  };
  ```
  `run()` calls `StemPlayer::render (r.stems, r.gains, r.startSec, r.endSec, r.speed, r.dest, [this] (float f) { progress = f; return ! threadShouldExit(); })` and sets `done` or `failed`. On a cancel (`threadShouldExit`), the state goes back to `idle`, not `failed`.
- **Produces:**
  - `void DragChip::setProgress (std::optional<float>)`: while set, the chip shows a 2 px cream line along its bottom at that fraction and doesn't start a drag.
  - `StemsScreen::setMixChip (const juce::String& text, std::optional<float> progress)`: the text, and the chip's width via `resized()`.
